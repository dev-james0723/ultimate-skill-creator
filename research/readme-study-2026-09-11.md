# README study: 30 popular skill-related repositories

Observation date: **2026-09-11**. Scope: public GitHub repository READMEs, not execution or source-code security audits.

## Method and limits

Discovery used GitHub repository search with:

```text
skill in:name,description stars:>3000 archived:false fork:false sort:stars-desc
```

The first 70 results supplied the candidate pool. We selected 30 high-star skill-focused repositories and collections, including several mixed skill/tooling projects when their README presented a reusable skill package. General programming exercises, standalone agent runtimes/apps, unrelated uses of “skill,” and index-only directories were not the focus. This is a purposive high-popularity sample, **not a provable global top-30 list**. Other relevant repositories can be missed by the query and selection boundary.

Popularity is repository stars, not installations, active users, the quality of an individual skill, or documentation effectiveness. Values below are GitHub's rounded displayed counts observed during this review, not exact API counts, and can change. Rows are ordered by the displayed count. A collection and a single-skill repository are different units; the type column makes that distinction explicit. `openai/skills` is retained as an explicitly deprecated historical comparator, not a current installation recommendation.

Each README was qualitatively inspected for entry-point/purpose, installation and first use, navigation, examples/outputs, scope, compatibility, safety, evidence, localization, and maintenance where present. The table identifies the inspected sections and records a synthesis rather than copying README text. This was not an exhaustive audit of every linked document, advertised claim, translation, installation command, or underlying script. Long READMEs were reviewed through their relevant sections. No percentage-frequency or causal claims are inferred from this review.

The source links resolve each repository's default-branch README. They are intentionally reviewable live references, not immutable snapshots. To reproduce this study later, capture each README's commit/blob SHA, exact star count, query, and retrieval timestamp first, then compare changed sections rather than presenting today's observations as permanent facts.

## Common patterns and conflicting styles

**Purpose and first use are the stable organizing questions, not a fixed visual template.** Obsidian and Emil's collections use thin indexes. Superpowers and ECC use extensive workflow and host-specific guidance. Humanizer and frontend-slides benefit from input/output demonstrations. The reusable pattern is to get a reader to the correct first action and observable result, while linking deeper material rather than imposing the longest format on every project.

**Install, invoke, and configure are different actions.** Matt Pocock's collection explicitly contrasts managed plugins with editable copies. Taste Skill distinguishes install names from folder names. The Obsidian and frontend-slides READMEs document directory and packaging pitfalls. The generator should ask for a verified route and exact entry point, not manufacture a generic marketplace command.

**Collections need routing, not just more prose.** Vercel's trigger examples, PM Skills' task-first entry points, marketing skills' shared-context relationship, and Nature Skills' shared package instructions motivate an optional catalog/dependency module. A single writing skill does not need that table.

**Compatibility claims require qualification.** Academic Research Skills describes inactive optional controls, AAS distinguishes structural validity from safety, and Scientific Agent Skills separates script testing from structural contracts. Accordingly, documentation must identify tested versus expected support and skipped checks. This is more useful than copying a “works with every agent” slogan.

**Proof and maintenance belong near the claim.** Caveman documents measurement caveats; planning-with-files distinguishes older benchmark behavior; OpenAI's catalog starts with a deprecation notice. A new skill must not inherit another project's test badge, performance number, maturity label, or outdated installation path.

**Style varies more than the core questions.** Tables suit task/skill/host comparisons. Numbered steps suit workflows. Short prose suits rationale and limits. Some projects use extensive badges, sponsor banners, diagrams, and multilingual navigation; others omit even a large title. Those visual features are optional, not a universal recipe. Real translated sections are useful; dead links and English placeholders presented as translations are not.

## Adopted convention versus observed practice

The implemented [universal README convention](../skill/ultimate-skill-creator/references/universal-readme-spec.md) uses eight compact content areas: installation, quick start, usage, compatibility, safety, validation, troubleshooting, and license. This is our design synthesis. It does **not** mean every sampled README has those eight headings. Safety, non-goals, truthful validation, and rights review remain mandatory review questions even when popular examples omit them.

Optional modules cover catalogs, configuration, architecture, benchmarks, maintenance, contributions, visuals, and localization. The [shared specification data](../skill/ultimate-skill-creator/assets/readme-spec.json) drives both [scaffolding](../skill/ultimate-skill-creator/scripts/create_skill_candidate.py) and [offline README lint](../skill/ultimate-skill-creator/scripts/validate_readme.py). The main [SKILL.md](../skill/ultimate-skill-creator/SKILL.md) loads the convention at README-authoring time rather than embedding this whole study into the runtime prompt.

The [Agent Skills specification](https://agentskills.io/specification) governs the installable format and progressive disclosure, not this README convention. Current [OpenAI skill documentation](https://developers.openai.com/codex/skills) is used for Codex setup; the deprecated catalog is evidence about maintenance communication only.
